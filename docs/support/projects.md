# 五个项目的接入路线

公共支持首先整合执行机制，各项目的业务语义、版本目录和教程归属保持明确。

## 首批两项试点

| 项目 | 场景 | 本地入口 | 新证据位置 |
| --- | --- | --- | --- |
| hello-shell | Bash 环境信息 | `docker:plan` / `docker:check` | `demos/bash/docker-pilot/` |
| hello-lang | Python 基础程序 | `docker:plan` / `docker:check` | `demos/python/docker-pilot/` |

Bash 使用原有 5.2 镜像锁；Python 使用原有 3.12 镜像锁，不与浏览器 Python 3.14 混为一谈。各自原采集命令与历史证据保留。

独立克隆时，可把工具仓库放在相邻目录，或设置 `HELLO_DOCKER_HOME`。离线入口只做校验和计划生成，Actions 才执行。

## 后续接入边界

- **hello-sql**：需要服务器/客户端镜像、应用就绪检查、查询会话和各数据库语义断言。浏览器专属数据库与托管服务不能虚构为 Docker 产品。
- **hello-mq**：保留消息拓扑、生产消费、重试、幂等和 Broker 状态断言；公共层统一 Compose 生命周期和原始采集。
- **hello-wasm**：通用镜像构建与锁定可共享；RISC-V 工具链、转换、运行时分片及浏览器验证继续由 WASM 项目维护。

## 接入前检查

明确输入版本、状态生命周期、成功条件、输出目录和清理范围。先选小场景试点，不把单容器验证扩写为整个产品已通过。

公共协议遇到无法表达的业务需求时，记录缺口并扩展协议与测试；不要把领域断言退化成“退出码零”或“文件存在”。
